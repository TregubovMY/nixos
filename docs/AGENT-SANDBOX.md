# Песочница агентов — как пользоваться

Практическая шпаргалка: что набрать, в каком порядке. Почему песочница
устроена именно так — `system-plan.md` §9; история решений и полный список
нюансов — `docs/REFERENCE.md`, разделы «Песочница для AI-агентов» и
«DeepSeek Harness (`dsh`) в agent-sandbox». Несколько аккаунтов Claude и
переключение между ними — раздел «Аккаунты Claude» ниже.

Ничего отдельно ставить не нужно — `agent-sandbox`, `claude` и `claude-use`
уже в PATH после `nixos-rebuild switch`.

## Идея в двух строках

- **Песочница = именованная группа проектов одного уровня доверия**, описанная
  конфигом `~/.config/agent-sandbox/projects/<имя>.conf`. Один долгоживущий
  контейнер на группу.
- **Все проекты группы лежат внутри по тем же путям, что на хосте**
  (`~/code/my/app` внутри — тот же `~/code/my/app`). Агент стартует там, где
  вы его запустили. Поэтому сессии Claude общие между хостом и песочницей, а
  пути в логах — те, что открывает IDE.

## Конфиг

```ini
# ~/.config/agent-sandbox/projects/my.conf
account = personal            # аккаунт Claude по умолчанию (необязательно)
rw      = ~/code/my           # проект, чтение+запись (повторяемо, минимум один)
rw      = ~/code/learn
rw      = ~/code/sfedu
ro      = ~/code/shared-lib   # проект только для чтения
publish = 3080:3080           # порт наружу, только на 127.0.0.1 хоста
env     = RAILS_ENV=development   # обычная переменная (секреты сюда не класть)
autostart = kandev start --backend-port 38429   # команда в фоне при старте
```

```ini
# ~/.config/agent-sandbox/projects/work.conf
account = work
rw      = ~/code/work/rnds
```

Конфиг держать **вне** всех смонтированных на запись папок (скрипт сам
откажется работать иначе) — иначе агент мог бы дописать себе доступ к
другим директориям. Новую папку в группу добавить = дописать строку и
`agent-sandbox down && agent-sandbox up`.

## Ежедневная работа

Стоите в любой папке проекта на хосте:

```bash
agent-sandbox                # shell в песочнице, которая покрывает эту папку, cwd тот же
agent-sandbox -- claude      # то же, сразу claude   (алиас: sclaude)
agent-sandbox @work -- claude   # явно выбрать песочницу (из любой папки; старт — в первом проекте)
agent-sandbox -C ~/code/my/other -- claude   # стартовать в другой папке группы
```

Песочница сама поднимается, если не запущена. Если папка входит в несколько
конфигов, выигрывает тот, чей путь длиннее. `up`/`down`/`status` нужны только
чтобы явно запустить (например с `autostart`) или остановить:

```bash
agent-sandbox up @work        # поднять в фоне + autostart-команды
agent-sandbox status          # какие поднятые
agent-sandbox down @work      # остановить (volume'ы с данными остаются)
```

## Аккаунты Claude

Хост и песочницы используют общий каталог `~/.local/share/claude-accounts/`:

```
shared/      то, что принадлежит вам: сессии (projects/), history, skills, plugins…
personal/    логин личного аккаунта + .claude.json   (остальное — симлинки в shared/)
work/        логин рабочего аккаунта + .claude.json
```

Сессия, начатая под одним аккаунтом, продолжается под другим — ради этого
`projects/` общий. Какой аккаунт активен (первое совпадение):

1. `CLAUDE_ACCOUNT=work claude …` — разово;
2. `claude-use <аккаунт>` — переключатель «до отмены», действует на хосте **и** в
   песочницах;
3. `account = …` в конфиге песочницы;
4. правила хоста `~/.config/claude-accounts/rules`:
   ```
   default = personal
   ~/code/work = work
   ```

Только для **одной** песочницы (остальные и хост не трогаем):

```bash
claude-use @work-rnds personal   # имя — как в @name конфига песочницы
claude-use @work-rnds --auto     # снять
```

Приоритет: `CLAUDE_ACCOUNT` → переключатель песочницы (`@имя`) → общий
`claude-use <аккаунт>` → `account =` из конфига → правила. Песочница узнаёт своё имя
из `AGENT_SANDBOX_NAME`, которое ставится при создании контейнера: у уже
запущенной до этой правки нужно `agent-sandbox down && up`.

Лимиты рабочего кончились:

```bash
claude-use personal          # теперь везде личный
claude --continue            # та же беседа
claude-use --auto            # вернуться к правилам (когда лимит сбросился)
claude-use                   # кто сейчас активен и почему
```

### Worktree kandev с хоста

Домашняя папка kandev (`~/.kandev`: БД, `master.key`, логи, worktree'ы задач)
лежит в томе песочницы — с хоста недоступна, поэтому `git worktree list` в
репозитории показывает worktree как `prunable`. Смотреть/запускать их пока можно
из песочницы (`agent-sandbox @work-rnds`, `cd ~/.kandev/tasks/<id>/<репо>`) либо
взять ветку на хосте (`git worktree add -f …`; не `git worktree prune` — сломает
worktree в kandev).

Пробовали (2026-10-20) перенести на хост **всю** домашнюю папку через
`KANDEV_HOME_DIR` и откатили: лишнее — на хост уезжают БД и `master.key`, нужны
симлинк и `git worktree repair`. Нужно только вынести worktree'ы в проект
(например `~/code/work/rnds/.worktrees`, один путь с обеих сторон): в бинарнике
kandev есть признаки настройки `worktree.base_path`/`worktree_root`, как она
включается и работает ли в 0.97.0 — не проверено. TODO.md.

### Общие настройки Claude для всех аккаунтов

Один блок в `modules/nixos/packages/claude-accounts.nix` (`baseSettings`) —
перед каждым запуском `claude` обёртка вливает его в `settings.json` текущего
аккаунта (`claude-use sync`; на хосте и в песочнице одинаково). Ключи блока
**перебивают** ручные правки в `settings.json`, остальные ключи аккаунта остаются.
Сейчас: без `Co-Authored-By`/подписи в PR и без ссылки на сессию (`attribution`),
модель `claude-sonnet-5-5`, режим разрешений `auto`, экономия токенов
(автосжатие на 400K вместо ~967K при окне 1M; без синхронизации скиллов и
коннекторов claude.ai, без Artifact, редкие скиллы выключены). Поменять — править блок и
`nixos-rebuild switch`; новый аккаунт получает его при первом запуске.
Уже запущенный `claude` настройки не перечитывает — перезапустить.

### Claude Code через npm: самообновление в песочнице

Nix-пакет `claude-code` неизменяем и обновляется только через `nix flake update`.
В песочнице есть записываемый том `npm-global` (`/shared/npm-global`, тот же, что у
`dsh`). При `agent-sandbox up` команда `agent-install` кладёт туда Claude Code и dsh
(`0.2.0-rc.2`), если их ещё нет; что ставить — ключ конфига `install = claude dsh`
(по умолчанию оба, `install = none` — ничего). Claude Code обновляется сам. Вручную:

```bash
agent-sandbox -- agent-install                              # повторить установку
agent-sandbox -- claude --version
agent-sandbox -- claude doctor                              # строка Auto-updates
```

Обёртка `claude` (`claude-accounts.nix`) запускает `$NPM_CONFIG_PREFIX/bin/claude`,
если он есть, иначе nix-бинарь — выбор аккаунта работает в обоих случаях.
Канал обновлений — `latest` (`autoUpdatesChannel` в общем блоке; `stable` — на неделю
старше, без релизов с крупными регрессиями). На хосте ничего не меняется:
там по-прежнему nix-пакет. Бинарь динамический, работает через `nix-ld`.
На хосте то же самое делает активация home-manager (`claudeCodeNpm` в `modules/home/mise.nix`): при `nixos-rebuild switch` ставит Claude Code в `~/.npm-global` через npm из mise, если его там нет; дальше он обновляется сам. Нет сети — остаётся nix-пакет.
Откат: `npm install -g @anthropic-ai/claude-code@2.1.300`. Версия больше не
закреплена в `flake.lock` — цена самообновления. Убрать: `npm uninstall -g
@anthropic-ai/claude-code`.

### Что есть в песочнице «из коробки» (по итогам прогона kandev-задачи, 2026-10-21)

- **git**: имя, e-mail, `includeIf` по каталогам (рабочая почта в рабочих папках),
  `init.defaultBranch`, `pull.rebase` берутся с хоста при `up` (файл
  `/etc/agent-gitconfig`), подпись gpg выключена. ssh нет: `fetch/pull/push` — на хосте,
  а `git` в песочнице сразу пишет об этом, а не «cannot run ssh».
- **postgres** (`initdb`, `pg_ctl`, `psql`), `file`, **tzdata** (`/usr/share/zoneinfo`,
  `TZDIR`) — агент раньше искал их в `/nix/store` и обходил руками.
- **Go**: `GOROOT` больше не подставляется от версии хоста (ломал Go другой версии),
  `mise reshim` при старте — `gofmt` и прочие бинарники находятся без правки `PATH`.

### Как запустить: `ai`, `aih`, `ais`

| Команда | Что делает |
|---|---|
| `ai [аргументы claude]` | сам выбирает: есть песочница, покрывающая папку → в ней; нет → напрямую на хосте |
| `aih` (= `ai --host`) | всегда напрямую на хосте |
| `ais` (= `ai --sandbox`) | всегда в песочнице: в настроенной, если папка в ней есть, иначе в одноразовой для **этой** папки |
| `ai --account work …` | разово под другим аккаунтом (хост и песочница) |
| `sclaude` | как раньше: claude в песочнице, покрывающей папку (без запасного варианта) |

Аргументы после наших опций уходят в `claude` как есть: `ai --continue`,
`aih --resume`, `ais -p "…"`. Наши опции — только длинные и только в начале.

**Любая папка в песочнице.** Папки нет в конфиге (например `~/code/nixos`)? —
`ais` (или `agent-sandbox --here`): создаётся контейнер ровно на эту папку,
без редактирования конфига. Один раз скачанные языки и npm общие у всех
таких контейнеров (том `adhoc`), сам контейнер на папку свой и живёт до
`agent-sandbox down`. `agent-sandbox status` показывает их как `here-<папка>-<хэш>`.
Нельзя `~` и `/` целиком. Аккаунт берётся из правил хоста по этой папке.

**Сессии общие всегда.** claude хранит беседы по пути рабочей папки, а все
песочницы монтируют проекты по тем же путям, что на хосте, и у всех аккаунтов
один `projects/`. Поэтому беседу, начатую `aih` в папке, продолжит `ais` или
`ai` в настроенной песочнице (`--continue`/`--resume`), и наоборот.
Проверено: в одноразовой песочнице для `~/code/nixos` виден тот же каталог
`projects/-home-max-code-nixos`, что и на хосте.

**Другой профиль на хосте.** Разово: `ai --account work` (или
`CLAUDE_ACCOUNT=work claude`). Пока не передумаете: `claude-use work`
(`claude-use --auto` — вернуться к правилам по папкам).

### Лимит в kandev: переключиться, не сбрасывая сессии

kandev запускает не `claude`, а адаптер, а тот — свой встроенный бинарник, в
обход обёртки. Поэтому в `autostart` kandev стартует с
`CLAUDE_CODE_EXECUTABLE=$(command -v claude)` (адаптер читает эту переменную):
обёртка выбирает аккаунт при **каждом** запуске агента, а не один раз при
старте kandev. Переключение:

```bash
claude-use personal      # на хосте, одной командой; kandev перезапускать не нужно
```

Дальше в kandev: перезапустить/продолжить упавшую сессию (новый процесс агента
уже пойдёт под `personal`). Беседа та же — транскрипты общие (`projects/`), kandev
возобновляет её штатно. Уже идущий процесс агента аккаунт не меняет, пока не
перезапущен. Вернуться: `claude-use --auto`. Если kandev стартовал по старой
записи автозапуска (`CLAUDE_CONFIG_DIR=…`), аккаунт зафиксирован до его
перезапуска — замените строку в конфиге песочницы и `agent-sandbox down && up`.

### Первая настройка (один раз)

Закройте все запущенные `claude` (и песочницы: `agent-sandbox down`), затем:

```bash
claude-use --import personal --yes   # переносит ~/.claude и ~/.claude.json в новую раскладку
claude-use --add work
CLAUDE_ACCOUNT=work claude           # внутри: /login под рабочим аккаунтом
```

Правила — файл на диске (как конфиги песочниц), не в Nix: пути у каждого свои.

### Добавить аккаунт

```bash
claude-use --add <имя>              # имя: [a-z0-9_-]; создаёт каталог аккаунта и симлинки на общее
CLAUDE_ACCOUNT=<имя> claude         # внутри: /login под нужной подпиской (один раз)
```

Дальше аккаунт можно: выбрать вручную (`claude-use <имя>`), назначить папке
(строка `~/code/путь = <имя>` в `~/.config/claude-accounts/rules`) или
песочнице (`account = <имя>` в её конфиге; работающую песочницу после этого
перезапустить — `down`, `up`). Сам аккаунт в песочнице заводить не нужно:
каталог аккаунтов общий с хостом.

### Нюансы

- `settings.json` и `CLAUDE.md` копируются при `--add`, дальше у каждого
  аккаунта свои (claude-code может переписывать файл через rename и заменил
  бы симлинк). Разрешения «always allow» придётся выдавать по аккаунтам.
- В песочнице видны логины **обоих** аккаунтов (каталог смонтирован целиком) —
  иначе нельзя переключаться без перезапуска. Аккаунты ваши, поэтому принято.
- `.claude.json` у каждого аккаунта свой (в нём идентичность и «доверенные
  папки»): в новом аккаунте claude один раз спросит доверие к папке.

## Поднять kandev + dsh в конфиге

Готовые `work.conf` и `my.conf` уже содержат обе доски (порты 38429/3080 и
38430/3090 — разные, чтобы песочницы работали одновременно).

Оба — обычные `autostart`-команды в конфиге, стартуют в фоне при `up` (лог —
`~/.local-state/autostart.log` внутри песочницы):

```ini
# ~/.config/agent-sandbox/projects/work.conf
account = work
rw      = ~/code/work/rnds

publish   = 38429:38429
autostart = kandev start --backend-port 38429

publish   = 3080:3080
autostart = dsh web --no-open --port 3081 --trusted-host 127.0.0.1:3080
autostart = socat TCP-LISTEN:3080,fork,reuseaddr TCP:127.0.0.1:3081
```

Зачем `socat`: `dsh web` сам отказывается слушать `0.0.0.0` ("would expose
remote code execution to the network") и слушает только `127.0.0.1:3081`
**внутри** контейнера, а `publish` пробрасывает наружу только порт самого
контейнера, не его loopback. `socat` принимает на `3080` (он `publish`-нут) и
форвардит на `127.0.0.1:3081`. kandev слушает сразу на нужном порту — ему
`socat` не нужен.

**Прокси хоста (Throne на `127.0.0.1:2080`).** podman сам копирует
`HTTP(S)_PROXY` хоста в контейнер, но `127.0.0.1` внутри — это сам контейнер,
и без прокси `npx` не мог скачать `@agentclientprotocol/claude-agent-acp`:
kandev падал с «Failed to start agent Claude» / `ACP initialize ... peer
disconnected`. Поэтому `agent-sandbox up` (и автозапуск при первом входе), если
прокси в окружении хоста — loopback, сам поднимает внутри `socat` на тот же
порт → `host.containers.internal`. Лог — `~/.local-state/autostart.log`.
Применяется при создании контейнера: для уже запущенного — `down && up`.

**Куда заходить** (с хоста, в браузере): kandev — http://127.0.0.1:38429,
dsh web — http://127.0.0.1:3080 (не 3081 — это внутренний порт).

**Разовая настройка после первого `up`:**

```bash
agent-sandbox @work -- dsh-setup     # ставит dsh + core-плагины (то же для @my — у каждой песочницы свой)
agent-sandbox down @work && agent-sandbox up @work   # dsh web подхватит плагины только при старте
```

Для kandev отдельно, один раз в его UI: Settings → Claude Code profile →
**CLI passthrough**.

## Первый раз в песочнице

Логин Claude не нужен — он общий с хостом (см. «Аккаунты Claude»). Остальное:

```bash
agent-sandbox @work
gh auth login        # если нужен gh (PR/issues)
opencode auth        # opencode хранит логин в home-volume песочницы
```

## Шпаргалка команд

| Команда | Что делает |
|---|---|
| `agent-sandbox [@имя] [-- cmd]` | выполнить cmd (по умолчанию shell) в песочнице; поднимет её, если не запущена |
| `agent-sandbox up [@имя]` | поднять в фоне + `autostart` |
| `agent-sandbox down [@имя]` | остановить |
| `agent-sandbox status` | какие песочницы подняты |
| `-C <папка>` | стартовать в этой папке (внутри песочницы) вместо cwd |
| `--no-tty` | без TTY (скрипты/оркестраторы) |
| `--gui` | видимое окно на десктопе — нужна живая Hyprland-сессия; фиксируется при создании |
| `--gitlab-token` | пробросить `GITLAB_TOKEN` (только Project Access Token, см. REFERENCE); при создании |
| `claude-use [аккаунт\|--auto\|--list\|--add имя]` | аккаунты Claude |

## Что сохраняется между `down`/`up`, что нет

- **Сохраняется** (home-volume песочницы): история shell, `~/.gitconfig`, dsh и
  его плагины/сессии, логин opencode, настройки инструментов.
- **Сохраняется, на песочницу** (не общее между песочницами): языки/рантаймы
  mise, `npm install -g`, `uv tool install`.
- **Не сохраняется**: сам контейнер и всё вне `~` и вне смонтированных папок
  (например `/tmp`).

## Установка версий языков

Если в проекте есть `.tool-versions`/`mise.toml`, нужная версия ruby/node/etc
ставится автоматически при старте в этой папке (`mise install`).

Шимы mise (`/shared/mise/shims`) стоят в `PATH` для **всех** процессов
песочницы, включая терминалы и агентов kandev (они стартуют мимо входа в
песочницу и worktree лежат в `~/.kandev/tasks`, вне ваших проектов — mise
доверяет им отдельно). Версия берётся из `.tool-versions`/`mise.toml`
папки; если конфига нет (например `mise.toml` не закоммичен, как у crypton) —
запасной вариант go 1.26 / node 24 / python 3 (`miseGlobalConfig` в
`modules/nixos/packages/agent-sandbox.nix`, подбирается по установленным на
хосте версиям). Go-модули качаются через прокси хоста в `~/go` (том
песочницы, кэш сохраняется между `down`/`up`); приватные модули по SSH
(`br.rnds.pro`) пока не пройдут — в песочнице нет `ssh`/ключа.

## IDE на хосте

Ничего пробрасывать не нужно: песочница монтирует те же папки (bind-mount, не
копия). Изолируется выполнение агента, не файлы, которые вы редактируете.

## Известные нюансы (кратко; полный список — REFERENCE.md)

- `--gui` требует реальной Wayland-сессии (Hyprland) на хосте.
- Ruby через mise подтверждён живьём. Node/Python/Go должны работать (nix-ld),
  но полным прогоном не обкатаны.
- Прокси в конфиге нет специально: Throne в TUN-режиме на хосте и так
  заворачивает весь трафик контейнеров.
- Остальные проекты группы агент видит всегда: изоляции **внутри**
  песочницы нет, граница — между песочницами и от остального хоста.
