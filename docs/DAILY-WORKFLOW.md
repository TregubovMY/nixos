# Как работать день в день

Это растущая шпаргалка — не разовый документ. Сюда идёт ответ на любой
"а как тут..." вопрос, который возникает по ходу использования системы
(не при установке/изменении конфига — то в `INSTALL.md`/`NIX-HOWTO.md`).
Новый вопрос — новый раздел или строчка здесь, а не только ответ в чате.

## Переход → просмотр → редактирование

`z <часть-имени>` ([zoxide](https://github.com/ajeetdsouza/zoxide) —
запоминает часто используемые папки по частоте использования, учится
сама на обычных `cd`) → `y` ([yazi](https://yazi-rs.github.io/) —
файловый менеджер в терминале: vim-клавиши, превью картинок/видео/PDF/
архивов; при выходе `q` терминал остаётся в той папке, где вышли) →
`Enter`/`o` на файле открывает его в `$EDITOR` (LazyVim, `nvim`).

Ничего из этого не требует конфига под проект — просто `cd`-итесь и
открывайте файлы как обычно, zoxide сам учится.

## Neovim (LazyVim)

Стоковый LazyVim (как именно настроен и почему — `REFERENCE.md`, раздел
«Neovim») + язык-экстра для Ruby (`ruby_lsp`/`rubocop`/`vim-rails`).

**Подсказки по сочетаниям клавиш** — нажать `<Space>` (leader) и
подождать: всплывает попап [which-key](https://github.com/folke/which-key.nvim)
со всеми доступными дальше клавишами, сгруппированными по смыслу
(`<leader>f` — файлы, `<leader>g` — git, `<leader>c` — код и т.д.). Так
же работает для любого префикса: `g`, `[`, `]`, `z`, `<c-w>`. `<leader>?`
— keymaps только текущего буфера. `:WhichKey` — всё дерево целиком.

**Полный официальный список сочетаний (таблицами, с фильтром по
extras):** <https://www.lazyvim.org/keymaps> — смотреть разделы Core и
Core plugins; разделы для языков/расширений, которые не включены
(Python, DAP, testing и т.п.), не относятся к текущей установке.

`<leader>gg` — lazygit прямо в редакторе.

## Терминал

**direnv** грузит проектное окружение сам при `cd` в папку с `.envrc`
(настроено системно, `modules/home/direnv.nix`). Подробный построчный
вывод (`direnv: export +AR +AS +CC ...`) — это нормальная диагностика:
какие переменные добавились/исчезли при входе/выходе из папки, не
ошибка. `nix-direnv: Using cached dev shell` значит окружение не
пересобиралось, взято из кэша — быстро. Если вывод мешает:
```bash
export DIRENV_LOG_FORMAT=
```

**zellij** (мультиплексор) и **ghostty** (терминал) — настроены с
дефолтными сочетаниями апстрима, см. `REFERENCE.md`, раздел «Shell,
Zellij, Ghostty, direnv», если нужны детали/история решений.

## Версии языков (mise)

Глобальные версии (go/node/python) уже стоят после установки
(bootstrap в `modules/home/mise.nix`). Добавить/сменить версию для
конкретного проекта — обычный mise, работает как у всех:
```bash
mise use node@22         # в папке проекта — пишет .tool-versions/mise.toml
mise use -g go@1.26.9    # глобально — пишет в ~/.config/mise/config.toml
```
Если `mise install <язык>` вдруг пытается собирать из исходников
(долго, и часто падает без тулчейна) — см. `NIX-HOWTO.md`, там же рецепт
для совсем старых версий (например Ruby 2.5.1), которым нужен другой
GCC.

## Docker / docker-compose

Работает как обычно — `docker compose up`/`docker-compose up` в папке
проекта. Под капотом это не настоящий Docker, а `podman` в
Docker-совместимом режиме (подробности и причины — `REFERENCE.md`,
раздел «podman + mise»). Логин в приватный registry — через Bitwarden,
см. `README.md`, таблица «Секреты».

## Открыть docx / xlsx / PDF / XML

- docx, xlsx, pptx, odt — LibreOffice (`libreoffice-fresh`, словари ru/en), двойной клик в Nautilus.
- PDF — Evince.
- XML — это текст: VS Code (`code файл.xml`) или neovim.

## Кончились лимиты рабочего Claude — как переключиться

```bash
claude-use personal     # везде (хост и песочницы) теперь личный аккаунт
claude --continue       # та же беседа, продолжается под другим аккаунтом
claude-use --auto       # когда лимит сбросился: вернуться к правилам (папка → аккаунт)
claude-use              # кто активен сейчас и почему
```

Запуск: `ai` (песочница, если папка в ней, иначе хост), `aih` (хост), `ais`
(песочница, для любой папки — одноразовая), `ai --account work` (разово другой
профиль). Сессии общие во всех вариантах. В kandev после смены аккаунта —
перезапустить сессию, не kandev: `docs/AGENT-SANDBOX.md`, «Лимит в kandev».

Подробности и первая настройка — `docs/AGENT-SANDBOX.md`, «Аккаунты Claude».

## Как провести задачу через агента (спека → код → ревью)

Пошагово — `docs/AI-AGENTS.md`, «Процесс задачи». Коротко: задача в

## Удалённый доступ и передача файлов

Порты открыты (`modules/nixos/remote-access.nix`), но **само по себе открытый
порт ничего не отдаёт** — за каждым стоит свой секрет:

| Что | Порт | Чем защищено | Как пользоваться |
|---|---|---|---|
| Удалённый экран (VNC) | 5900/tcp | одноразовый пароль + свежий TLS-сертификат на сеанс; слушает только пока вы сами запустили | на этой машине: `remote-screen` (печатает адрес, логин `remote`, пароль; закрывается через 1 час или по Ctrl-C). `remote-screen -t 30m`, `--view-only` (только смотреть), `--real` (настоящий экран вместо виртуального монитора `VNC-1`) |
| SSH | 22/tcp | только ключ (пароль отключён), 3 попытки, fail2ban банит перебор | свой публичный ключ — в `~/.ssh/authorized_keys` этой машины; с другой: `ssh max@<адрес>` |
| Файлы (LocalSend) | 53317 tcp+udp | каждый входящий файл нужно подтвердить; PIN — в настройках LocalSend | открыть LocalSend, вкладка «Получить»; на телефоне/ноутбуке — то же приложение |
| Телефон (KDE Connect) | 1714–1764 | спаривание с подтверждением | свой модуль, firewall открывает сам |

**Подключиться к удалённому экрану этой машины** (с другого компьютера): VNC-клиент
(на Linux — Remmina, протокол VNC), адрес из вывода `remote-screen`, порт 5900,
логин `remote`, пароль из того же вывода. Клиент спросит про сертификат — это
сертификат на один сеанс, соглашайтесь. Не подключается через интернет? Так и
задумано — см. «Только своя сеть» ниже: наружу ходите через SSH-туннель
(`ssh -L 5900:localhost:5900 max@<адрес>`, затем VNC на `localhost:5900`).

**Подключиться С этой машины к другой:** Remmina (VNC/RDP/SSH), адрес и
пароль берёте на той стороне. Для VNC-сервера на другой Linux-машине — то же
`remote-screen`.

**Пароль LocalSend:** Настройки → «PIN» — тогда без PIN отправитель не сможет
начать передачу, даже если вы случайно нажмёте «принять».

**Только своя сеть.** По умолчанию порты открыты только для частных адресов
(`192.168/16`, `10/8`, `172.16/12`) — `remoteAccess.lanOnly = true`. Контейнеры
песочницы агентов (podman) на эти порты не пускает отдельное правило. Из
интернета достучаться нельзя; домашний роутер тоже закрывает вход. Открыть для
всех адресов: `remoteAccess.lanOnly = false;` в `hosts/<имя>/configuration.nix`
(и тогда обязательно держите fail2ban и ключи; VNC — по-прежнему только пока
запущен `remote-screen`). В кафе/общей сети `192.168.x.x` тоже «частная» —
там `remote-screen` лучше не запускать, а SSH остаётся только по ключу.

**Как открыть свой порт.** В `hosts/<имя>/configuration.nix` (или в модуле):
`networking.firewall.allowedTCPPorts = [ 8081 ];` — для всех адресов;
для одного интерфейса — `networking.firewall.interfaces."wlan0".allowedTCPPorts`.
После правки: `nix flake check --no-build`, `nixos-rebuild dry-build`, затем
`switch` (см. `docs/NIX-HOWTO.md`). Временно, до перезагрузки, без правки
конфига: `sudo iptables -I nixos-fw -p tcp --dport 8081 -j nixos-fw-accept`.
Посмотреть, что реально слушает машина: `ss -ltnup`.

## Известные баги (не наши, ждём фикса апстрим)

- **Иконка Bitwarden не всегда появляется в трее DMS.** Подтверждённый
  race condition в Quickshell (на котором DMS построен) —
  [issue #1190](https://github.com/quickshell-mirror/quickshell/issues/1190),
  фикс есть в открытом PR, не влит. Обход: перезапустить Bitwarden после
  полной загрузки DMS; системного фикса нет.

## Горячие клавиши (сверх стандартных DMS)

| Клавиши | Действие |
|---|---|
| SUPER+/ | шпаргалка всех клавиш DMS |
| Win (короткое нажатие) | поиск приложений (лаунчер DMS); запасной — SUPER+Space |
| SUPER+E | файловый менеджер (Nautilus) |
| `y` (в терминале) | терминальный файловый менеджер yazi; при выходе (`q`) терминал остаётся в той папке |
| SUPER+T | терминал (ghostty) |
| SUPER+X | меню питания (выход, перезагрузка) |
| SUPER+L | заблокировать экран (живые обои продолжают крутиться) |
| SUPER+ALT+L | заблокировать и погасить мониторы |
| SUPER+Tab | переключение между окнами (удерживать, Tab/Shift+Tab — цикл, отпустить SUPER — подтвердить, Esc — отмена) |
| CapsLock | переключить раскладку en/ru |
| Print / SHIFT+Print / SUPER+Print | скриншот области / экрана / окна |
| SUPER+SHIFT+Print | скриншот области с рисованием (swappy) |
| SUPER+SHIFT+R / SUPER+CTRL+R | запись области / экрана (повтор — стоп) |
| SUPER+ALT+T | перевести выделенный текст (Dialect) |
| Ctrl+Shift+C/V (в терминале) | копировать/вставить |

### Где менять сочетания

1. **Быстро, мышью:** SUPER+запятая → раздел Keybinds в настройках DMS — там
   поиск по всем сочетаниям и переопределение существующих.
2. **Навсегда и на всех машинах:** блок `NIXOS-MANAGED BINDS` в
   `modules/home/hyprland.nix` (там же сочетания из таблицы выше) — один
   `nixos-rebuild switch`, и они на месте. Формат:
   `hl.bind("SUPER + E", hl.dsp.exec_cmd("nautilus"))`. Править прямо файл
   `~/.config/hypr/dms/binds-user.lua` между строками `NIXOS-MANAGED` бесполезно:
   блок перезаписывается при каждой перестройке.
3. Файлы DMS (`~/.config/hypr/dms/binds.lua`) — его стандартные сочетания,
   их пишет сам DMS.
