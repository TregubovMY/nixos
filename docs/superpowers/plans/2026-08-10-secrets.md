# Secrets (sops-nix, GPG key) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A minimal `modules/nixos/secrets.nix` (sops-nix) for the one secret that stayed after SSH keys and Throne's proxy config moved to Bitwarden — the GPG key used for signing git commits. Verified via sops-nix's own real `ssh-keys` test pattern (a genuine `ssh-to-age` conversion, not a shortcut), adapted to this repo. Full rationale: `docs/superpowers/specs/2026-08-10-secrets-design.md`.

**Architecture:** `modules/nixos/secrets.nix` wires `sops.defaultSopsFile`, `sops.age.sshKeyPaths` (ssh-to-age from the host's own SSH host key), and `sops.secrets."gpg_key"`. `secrets/secrets.yaml`/`.sops.yaml` are **not** created with real content by this plan — no real host exists yet to encrypt them for. Verification uses a vendored copy of sops-nix's own `ssh-keys` test fixtures (a fixed, publicly-known test SSH key + a `secrets.yaml` genuinely encrypted for it) rather than inventing a new test mechanism.

**Tech Stack:** `sops-nix` (new flake input, `github:Mic92/sops-nix`), `pkgs.testers.runNixOSTest` (same helper already used by the Secure Boot plan's vendored test — confirmed to be sops-nix's own choice too, not lanzaboote-specific).

## Global Constraints

- `secrets/secrets.yaml` and `.sops.yaml` with **real** content are explicitly out of scope — they need a real host's real SSH-derived age recipient, which doesn't exist until `hosts/mimir/` is installed for real. Do not fabricate placeholder "real" content; the module is complete and mergeable without them.
- The vendored test fixtures (`ssh-key`, `secrets.yaml` from sops-nix's `pkgs/sops-install-secrets/test-assets/`) must be fetched fresh from the actual pinned `sops-nix` rev at implementation time and verified byte-identical — don't hand-copy content from this plan's text (none is embedded here for exactly that reason: risk of a transcription error in key material, however throwaway).
- Disk-budget check (per `CLAUDE.md`) before Task 3's build: GC first if projected free space would drop under ~5GB.
- `install.determinate.systems` substituter is unreachable in this sandbox — always pass `--option substituters "https://cache.nixos.org/" --option extra-substituters ""` on build/check commands.
- Every non-trivial `.nix` file gets WHY-comments per `CLAUDE.md`.
- GitHub's unauthenticated API rate limit (60 req/hour) has been hit multiple times this session while locking new flake inputs or fetching source files — if hit, this is a real external wait (poll with real `sleep`, don't hammer), not a bug to route around.

- [ ] **Step 2: Write `modules/nixos/secrets.nix`**

```nix
# Minimal sops-nix wiring for the one secret that survived the move to
# Bitwarden (system-plan.md §6/§7, 2026-08-10) — the GPG key used to sign
# git commits. SSH keys and the Throne proxy config went to Bitwarden
# instead; sops-nix's remaining scope is this narrow on purpose, not an
# oversight.
#
# sops.age.sshKeyPaths derives the age decryption key from the host's own
# SSH host key (ssh-to-age) — this only works once a real host has
# generated one, which hosts/mimir/ hasn't (doesn't exist yet). This
# module is complete and buildable without that: secrets/secrets.yaml with
# real content, and .sops.yaml with a real recipient, are added as a
# real-install-time follow-up (see docs/superpowers/specs/
# 2026-08-10-secrets-design.md "Real Install Boundary") — not this plan's
# job. Verified via a vendored copy of sops-nix's own ssh-keys test
# instead (see modules/nixos/secrets-test/), which proves the mechanism
# without needing a real host's key to exist.
{ ... }:
{
  sops.defaultSopsFile = ../../secrets/secrets.yaml;
  sops.age.sshKeyPaths = [ "/etc/ssh/ssh_host_ed25519_key" ];
  # Consumed later (git commit signing config) once a home-manager/user
  # config layer exists — config.sops.secrets."gpg_key".path is the
  # decrypted file's path once that layer is built. Not this plan's job.
  sops.secrets."gpg_key" = { };
}
```

- [ ] **Step 3: Syntax-check**

Run: `nix-instantiate --parse modules/nixos/secrets.nix flake.nix`

- [ ] **Step 4: Commit**

## Task 3: Vendored sops-nix decryption test

**Files:**
- Create: `modules/nixos/secrets-test/` (vendored fixtures + test file)
- Modify: `flake.nix` (add `checks.${system}.secrets-decryption`)

**Interfaces:**
- Consumes: `sops-nix` flake input (Task 1) — its own test fixtures, fetched fresh in this task.

This task has real research/adaptation work, similar in kind (though smaller in scope) to Task 3 of the disk/boot and Secure Boot plans.

- [ ] **Step 1: Fetch sops-nix's real test source and fixtures**

Confirm the actual pinned `sops-nix` rev from `flake.lock` (after Task 1/2), then fetch from that exact rev (not assumed `master` — pin drift is possible):
- `checks/nixos-test.nix` — read the whole file. The relevant test is `ssh-keys`:
  ```nix
  ssh-keys = testers.runNixOSTest {
    name = "sops-ssh-keys";
    nodes.server = { ... }: {
      imports = [ ../modules/sops ];
      services.openssh.enable = true;
      services.openssh.hostKeys = [
        { type = "rsa"; bits = 4096; path = testAssets + "/ssh-key"; }
      ];
      sops.defaultSopsFile = testAssets + "/secrets.yaml";
      sops.secrets.test_key = { };
    };
    testScript = ''
      start_all()
      server.succeed("cat /run/secrets/test_key | grep -q test_value")
    '';
  };
  ```
  where `testAssets = ../pkgs/sops-install-secrets/test-assets`.
- `pkgs/sops-install-secrets/test-assets/ssh-key` (the fixed RSA private key — confirmed real and safe to vendor, same category as the Secure Boot plan's vendored UEFI test keys: a published, throwaway fixture, not a secret that protects anything real) and `pkgs/sops-install-secrets/test-assets/secrets.yaml` (real sops-encrypted content, verified against the recipient that key converts to via `ssh-to-age`).

- [ ] **Step 2: Vendor the fixtures and write the test**

Recommended default (matches the disko/lanzaboote precedent): vendor (copy), don't live-reference into the `sops-nix` flake input's internal file layout. Create:
```
modules/nixos/secrets-test/
  ssh-decryption.nix       # the adapted test (pkgs.testers.runNixOSTest)
  fixtures/
    ssh-key                # vendored, byte-identical to sops-nix's test-assets/ssh-key
    secrets.yaml            # vendored, byte-identical to sops-nix's test-assets/secrets.yaml
    README.md                # explains why the committed private key isn't a secret —
                              # same pattern as modules/nixos/secure-boot-test/fixtures/
                              # uefi-keys/README.md from the Secure Boot plan
```

The test itself should end up close to upstream's `ssh-keys` test, with a WHY-comment explaining: this test does NOT prove anything about `hosts/test-secrets/` or real GPG key content — it proves the sops-nix mechanism (real `ssh-to-age` conversion + activation-time decryption) works in this repo's context, using a fixed test key that stands in for a real host's SSH key. Real recipient/key generation is a real-install-time step (see the design doc).

Naming the secret `test_key` (matching upstream exactly, simplest) vs. re-encrypting a fresh fixture with the secret named `gpg_key` (closer to this repo's real module, needs `sops`/`age` available to re-encrypt against the same public recipient from `fixtures/age-keys.txt`'s public key — vendor that file too if you take this path) — either is acceptable per the design doc; use your judgment, note which you picked and why in your report.

- [ ] **Step 3: Wire into `flake.nix`**

```nix
checks.${system} = {
  disko-luks-btrfs = disko.lib.testLib.makeDiskoTest { /* unchanged */ };
  secure-boot-signing = pkgs.testers.runNixOSTest { /* unchanged */ };

  # Confirms sops-nix's ssh-to-age decryption mechanism actually works in
  # this repo's context, via a vendored copy of sops-nix's own upstream
  # test (fixed test SSH key standing in for a real host's, which doesn't
  # exist yet — see modules/nixos/secrets-test/ssh-decryption.nix and
  # docs/superpowers/specs/2026-08-10-secrets-design.md). Does NOT touch
  # hosts/test-secrets/ or modules/nixos/secrets.nix's real
  # sops.age.sshKeyPaths path.
  secrets-decryption = pkgs.testers.runNixOSTest (import ./modules/nixos/secrets-test/ssh-decryption.nix);
};
```
Adjust the exact form to match what Step 2 actually produced (e.g. if the test file already returns the full `testers.runNixOSTest { ... }` call rather than just the argument attrset, wire it accordingly — don't force it into a shape it doesn't have).
