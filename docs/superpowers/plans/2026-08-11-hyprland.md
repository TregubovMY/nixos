# Hyprland Module + Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `modules/nixos/hyprland.nix` — `programs.hyprland.enable` plus the rest of `system-plan.md` §5.2's package list — verified via eval + dry-build (no VM boot, no real Hyprland config content). Full rationale, including the package-naming research findings: `docs/superpowers/specs/2026-08-11-hyprland-design.md`.

**Architecture:** One new module, no module arguments (nothing host-specific), no new flake input (everything comes from the already-present `nixpkgs`). A throwaway `hosts/test-hyprland/` host (mirrors `hosts/test-desktop-apps/`'s shape) proves it evaluates and dry-builds.

**Tech Stack:** Plain nixpkgs packages + the `programs.hyprland` NixOS module — no new flake inputs.

## Global Constraints

- No real Hyprland configuration content (keybinds, waybar widgets, theme, `exec-once` autostart) — see design doc "Out of Scope". That's a future `modules/home/*` task.
- No `xdg-desktop-portal-hyprland` entry in `environment.systemPackages` — `programs.hyprland.enable` already defaults `portalPackage` to it (verified, see design doc "Research findings").
- Every non-trivial `.nix` file gets WHY-comments per `CLAUDE.md`.
- This sandbox's `install.determinate.systems` substituter is unreachable — always pass `--option substituters "https://cache.nixos.org/" --option extra-substituters ""` on `nix build`/`nix flake check` commands.
- GitHub's unauthenticated REST API can rate-limit this sandbox's shared IP on flake-input resolution (hit during the home-manager round) — not expected to matter here since this plan adds no new flake input, but if any `nix` command errors with "API rate limit exceeded", back off ~45s and retry rather than treating it as a real failure.

- [ ] **Step 1: Write `modules/nixos/hyprland.nix`**

```nix
# Hyprland compositor + its supporting package stack (system-plan.md
# §5.2). programs.hyprland.enable already defaults xdg.portal.enable,
# portalPackage (-> xdg-desktop-portal-hyprland), and xwayland.enable to
# working values -- confirmed by evaluating the module's real option
# defaults against this repo's pinned nixpkgs (see
# docs/superpowers/specs/2026-08-11-hyprland-design.md "Research
# findings"), not assumed from §5.2's flat package list. No real Hyprland
# config content here (keybinds, waybar widgets, theme, exec-once
# autostart) -- that needs home-manager dotfiles (modules/home/*, not
# built yet), a separate later task, same boundary the desktop-packages
# and home-manager rounds already drew.
{ pkgs, ... }:
{
  programs.hyprland.enable = true;

  environment.systemPackages = with pkgs; [
    waybar
    fuzzel
    mako
    hyprlock
    hypridle
    grim
    slurp
    wf-recorder
    hyprpaper
    cliphist
    wl-clipboard
    # Hyprland's own polkit agent, not polkit-gnome -- system-plan.md
    # §5.2 left this an open either/or; hyprpolkitagent is actively
    # maintained by the Hyprland project itself and purpose-built for
    # this exact compositor rather than borrowed from GNOME. See design
    # doc "Research findings" for the full comparison.
    hyprpolkitagent
    # qt5ct/qt6ct + kvantum: system-plan.md §5.2's single "qt5/qt6ct +
    # kvantum" bullet is actually four separate packages at non-obvious
    # attribute paths -- bare qt6ct doesn't exist (renamed), bare qt5ct
    # doesn't exist either (needs libsForQt5 prefix). Confirmed against
    # this repo's pinned nixpkgs via nix eval, not assumed.
    libsForQt5.qt5ct
    qt6Packages.qt6ct
    libsForQt5.qtstyleplugin-kvantum
    kdePackages.qtstyleplugin-kvantum
  ];
}
```

## Task 2: Throwaway host + verification

**Files:**
- Create: `hosts/test-hyprland/configuration.nix`
- Modify: `flake.nix` (register `nixosConfigurations.test-hyprland`)

**Interfaces:**
- Consumes: `modules/nixos/boot.nix` (existing, unmodified), `modules/nixos/hyprland.nix` (Task 1).

- [ ] **Step 1: Write `hosts/test-hyprland/configuration.nix`**

```nix
# Throwaway verification host for the Hyprland module + package list —
# NOT a real target machine, and NOT hosts/mimir/. Mirrors
# hosts/test-desktop-apps/'s shape exactly (ext4 /dev/vda1 + grub, no
# qemu-vm.nix import, no VM boot) -- same testing depth, see
# docs/superpowers/specs/2026-08-11-hyprland-design.md "Testing" for why:
# programs.hyprland.enable is structurally the same kind of thing as
# programs.throne.enable/programs.kdeconnect.enable, both already proven
# there. No nixpkgs.config.allowUnfree needed -- every package in
# hyprland.nix is FOSS (confirmed at design time, re-confirmed for real
# by this host's own dry-build below).
{ ... }:
{
  imports = [
    ../../modules/nixos/boot.nix
    ../../modules/nixos/hyprland.nix
  ];

  fileSystems."/" = { device = "/dev/vda1"; fsType = "ext4"; };
  boot.loader.grub.device = "/dev/vda";

  system.stateVersion = "24.05";
}
```

- [ ] **Step 2: Register `nixosConfigurations.test-hyprland` in `flake.nix`**

- **Никакого реального Hyprland-конфига** — кейбинды, виджеты waybar,
  тема, `exec-once`-автозапуск (включая будущую привязку

  нет `users.users.*`/`home-manager.users.*` (см. skeleton и
  home-manager design docs).
