# Работа с AI-агентами

Два режима — выбор зависит от задачи, не от инструмента (один и тот же
`claude`/`opencode`, разница — где он запущен).

## Разовый вопрос — прямо на машине

```bash
ai          # = claude на хосте, в этой папке (или просто claude / opencode)
```
`claude`/`opencode` стоят системно (`modules/nixos/desktop-apps.nix`,
§5.5 в `system-plan.md`). Для быстрого вопроса и правок в своих проектах —
этого достаточно.

## Работа с кодом в изоляции — VM

Для чужого кода, задач с Docker и долгих автономных задач — **agent-vm**:
одна microVM со своим ядром, Docker, Postgres/Redis, интернет только через
фильтрующий прокси, без доступа к LAN, ssh-ключам и остальному `~`. Папки
проектов из `agentVm.mounts` видны по тем же путям, сессии Claude общие с хостом.

```bash
agent-vm up                    # один раз после загрузки
cd ~/code/my/app && aiv        # claude в VM в этой папке (= ai --vm)
claude-use personal            # кончились лимиты рабочего — переключить аккаунт
```

Полная шпаргалка (конфиг, что общее с хостом, аккаунты Claude, риски) —
**`docs/AGENT-VM.md`**. История решений — `docs/REFERENCE.md` «agent-vm».
(Podman-песочница `agent-sandbox` убрана 2026-11-02, живёт в ветке `agent-sandbox`.)

## Доски (kandev, DeepSeek Harness)

kandev и `dsh web` поднимаются сами внутри VM: http://127.0.0.1:38429 и
http://127.0.0.1:3080 после `agent-vm up` (`docs/AGENT-VM.md` «Доски»).

## Процесс задачи (шаблон `llm-dev-template`)

Готовый процесс «задача → спека OpenSpec → ревью → код → ревью → архив»
живёт в отдельном репозитории `~/code/my/llm-dev-template` (workflow
kandev, правила агента `AGENTS.md`, навыки, pre-commit). Здесь только
как им пользоваться; устройство и причины — README и ADR того репозитория.

Первый запуск на проекте:

1. `~/code/my/llm-dev-template/init.sh ~/code/proj` — режим `--team` (по
   умолчанию): для командных репозиториев. В git проекта **не попадает ничего**
   (файлы скрыты через `.git/info/exclude`, правила агента — личные
   `.agents/PROCESS.md` + `CLAUDE.local.md`, спеки OpenSpec локальные и не
   коммитятся, формат коммитов — по соглашению проекта). Проверьте: `git status`
   чистый. Для своих репозиториев — `init.sh --own` (всё коммитится: `AGENTS.md`,
   lefthook, commitlint). Существующие файлы не трогает.
2. В проекте: `scripts/checks` — вписать команды format/lint/typecheck/unit.
3. `agent-vm up` (kandev: http://127.0.0.1:38429), в kandev
   Settings → Workspaces → Workflows → Import → `.kandev/workflow.yml`.
   Профиль Claude Code — **CLI passthrough**.

Каждая задача:

1. Бэклог: создать задачу, название с ключом (`SENTINEL-1317 …`), описание —
   текст тикета, **предварительно прогнанный через `scripts/scrub`**.
2. Перенести на «Спека» — агент пишет спеку и останавливается; вы ревьюите
   (Review → комментарии → Fix comments) и сами переносите на «Реализация».
3. «Реализация» → «Проверки и ИИ-ревью» идут сами; читаете
   `.reports/<KEY>/ai-review.md`, возвращаете на «Реализацию» или двигаете в
   «Ревью кода».
4. «Ревью кода»: дифф, комментарии, Fix comments. Довольны — на «Отчёт».
5. «Отчёт»: читаете `.reports/<KEY>/`; одобрили — на «Архив» (агент
   архивирует спеку последним коммитом). Push, MR, комментарий в Jira — вы.

Агент рассуждает на английском, отвечает и пишет спеки по-русски. Режим
проекта (`team`/`own`) лежит в `.agents/mode`; в `team` агент не коммитит
спеки — в MR уходит только код. Новый клон или worktree командного проекта —
`init.sh` запустить заново (исключения локальны для клона).

## IDE

VM монтирует папки проектов с хоста по тем же путям — открывайте их в
IDE на хосте как обычно; агент в VM видит те же файлы. Порты dev-сервера
из VM — `agent-vm forward <порт>`.
