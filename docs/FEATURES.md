# Фишки системы (для переноса на другую машину/ОС)

Не "как это работает в Nix" (то в `system-plan.md`/`REFERENCE.md`), а
**что именно делает систему удобной** — список, по которому можно
понять, что стоит повторить на другой системе (не обязательно NixOS),
чтобы не потерять удобство. Каждая строка — ссылка туда, где реальная
реализация/детали.

## Безопасность диска и загрузки

| Фишка | Детали |
|---|---|
| Полное шифрование диска (LUKS) + btrfs, пароль спрашивается один раз при загрузке | `system-plan.md` §4 |
| Secure Boot со своими ключами (lanzaboote) | `system-plan.md` §4, `docs/REFERENCE.md` «Secure Boot (lanzaboote)» |

## Секреты — без отдельного шифрующего механизма в git

Всё (SSH-ключи, GPG-ключ, конфиг прокси, логин в docker-registry,
пароли/TOTP) — в Bitwarden как secure note, руками на новую машину.
Один принцип для всего — не нужно заводить sops/age/pass отдельно.
**`README.md`, раздел «Секреты (Bitwarden)»** — таблица "что/куда/что
сделать"; почему именно так — `system-plan.md` §6/§7.

Отдельная приятная деталь: **SSH-agent — сам Bitwarden Desktop**
(Settings → SSH agent), не отдельный `ssh-agent`/`gnome-keyring` —
значит ключи уже разблокированы тем же unlock, что и весь остальной
vault, без второго пароля.

## Навигация и редактирование в терминале

Связка **zoxide → yazi → nvim** ("jump → browse → edit") — быстрый
`cd` по частым папкам, файловый менеджер с превью, редактор; LazyVim с
`which-key` для подсказок по сочетаниям на ходу, без запоминания
наизусть. **`docs/DAILY-WORKFLOW.md`** целиком об этом.

## AI-агенты в изоляции

Claude Code/OpenCode работают в rootless-контейнере, не видят остальной
`~` — можно давать агенту доступ к сети и инструментам без риска для
остальных проектов/ключей на машине. **`docs/AI-AGENTS.md`** — вход;
**`docs/AGENT-SANDBOX.md`** — полная шпаргалка.

## Прокси (обход geo/санкционных блокировок)

Throne (sing-box) с маршрутизацией по доменам: российское — напрямую,
остальное — через прокси, корпоративные домены — напрямую отдельным
правилом. Не TUN-режим (весь трафик), только то, что реально заблокировано.
`docs/REFERENCE.md` «Прокси и рабочий VPN»; подробный разбор правил
sing-box и типичных ошибок — отдельный документ в репозитории
инфраструктуры VPN-сервера (не здесь), искать `throne-routing.md`.

Автоочистка стора по расписанию + защита от ENOSPC при сборке — не

стора»; дисциплина разработки (check → dry-build → build-vm, бюджет
места) — `CLAUDE.md`.
