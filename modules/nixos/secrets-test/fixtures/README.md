# Test-only SSH host key and sops fixture — NOT secrets

`ssh-key` (an ed25519 `-----BEGIN OPENSSH PRIVATE KEY-----` block) and
`secrets.yaml` in this directory are sops-nix's own **published,
throwaway** upstream test fixtures, vendored byte-identical from
`Mic92/sops-nix` (rev `f1406619a3884cd5c47992a70b8b35c9c0fcb4c9`, matching
this repo's `flake.lock`) — not generated by or specific to this
repository, and not used anywhere near a real machine. Upstream paths:
`pkgs/sops-install-secrets/test-assets/ssh-ed25519-key` (renamed to
`ssh-key` here, see `../ssh-decryption.nix`'s header comment for why the
ed25519 variant was chosen over upstream's RSA `ssh-key`) and
`pkgs/sops-install-secrets/test-assets/secrets.yaml`.

**Why `ssh-key` is safe to commit despite containing a private key
block**, per `CLAUDE.md`'s hard rule against committing secret material:
it secures nothing real. It exists only so
`../ssh-decryption.nix` can hand it to `services.openssh.hostKeys` inside
a throwaway QEMU VM, letting sops-nix convert it (via `ssh-to-age`) into
the age identity that decrypts `secrets.yaml` during `nix flake check -L`.
It is never used by, referenced from, or reachable by this repo's real
`modules/nixos/secrets.nix` module, which derives its actual decryption
key from `/etc/ssh/ssh_host_ed25519_key` — a real host key that doesn't
exist yet (no real host has been installed). Same public source, same
public fixture as anyone who clones `Mic92/sops-nix` and runs its test
suite (`nix flake check` in that repo exercises this exact key/file pair).

**Why `secrets.yaml` is safe to commit despite being a real, genuinely
sops-encrypted file**: the only age recipient it decrypts against here is
the one derived from `ssh-key` above (confirmed by hand: `ssh-to-age
-private-key -i ssh-key` followed by `sops -d secrets.yaml` with
`SOPS_AGE_KEY_FILE` pointed at the result yields `test_key: test_value` —
the exact content upstream's test asserts). It also contains other
sops-internal recipients (additional age keys, several PGP entries) from
upstream's own test suite that are irrelevant here; none of them are
usable or meaningful outside upstream's own CI. This file is completely
decoupled from `secrets/secrets.yaml` (this repo's real, separately
encrypted secrets file, see `modules/nixos/secrets.nix`) — different file,
different recipients, different purpose.
